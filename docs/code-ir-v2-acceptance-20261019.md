## 本轮范围

仓库 → 项目/环境识别 → SCIP 语义事实 + 成熟 AST 结构 → 持久化 Code IR → 校验 → 可重建 SQLite。没有 Agent 服务、MCP、插件入口或问答界面。

- TypeScript 配置 API 读取 JSONC、extends、references，并按真实配置划分单元。
- Python 配置使用 TOML/JSONC 解析，按组件记录配置、环境和推断缺口。
- 规范化实体 ID、符号状态、出处、源码定位与原始生产者数据同时保存。
- AST 提取声明、参数、签名、导入及调用位置；调用关联必须有 SCIP 定位证据。
- SQLite 从保存的 IR 原子重建，完整记录保存在 `ir_records`。

## 校验、耗时与体积

30 项自动化测试全部通过，覆盖真实 Python/TS 索引、跨文件静态目标、配置分离及失败、局部符号作用域、getter 误判防护、动态表达式、Unicode 编码不确定性、实体损坏、源码校验、旧 v1 兼容和原仓库移走后的 SQLite 重建。依赖使用官方 npm registry 审计，结果为 0 个已知漏洞。

真实产物通过 1,042 项文件校验与跨实体一致性验证。生产者未声明位置编码的 191,336 个范围只校验行与顺序，未声称完成列边界验证。旧 v1 真实产物仍可离线校验。

第一次完整扫描中，发现 Python AST 反复切割整份源码导致超时，失败产物保留在 `scan-LV1alv`。优化为预计算行字节后，再次验证输入与配置指纹不变，复用该次扫描的 14 份原始 SCIP，重做结构提取、规范化、校验和 SQLite 重建，生成最终 `scan-IvEOIP`。这不是一次新的端到端索引计时，也不是已经实现增量扫描。

- 完整扫描的项目发现约 9.42 秒，SCIP 索引约 111.29 秒。
- 优化后重放：准备 0.36 秒，结构提取与 IR 保存 8.39 秒，校验及 SQLite 重建 13.36 秒，总计 22.11 秒。
- 规范化 IR 连同源码、原始 SCIP 和配置/环境快照：337,717,257 字节（约 322.1 MiB）。
- 完整 SQLite 投影：455,684,096 字节（约 434.6 MiB）。原始执行目录还保留额外日志和 SCIP，不包含在上述 IR 体积中。

上述时间为本机单次观察值，不是性能保证。SQLite 完整镜像与兼容查询表会重复存储部分数据，目前优先保证可检查和可重建。
